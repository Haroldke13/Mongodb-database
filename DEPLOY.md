# Deploying `Mongodb-database`

A finished, self-contained Flask + PyMongo to-do list. Add a task with a
"degree" (priority), delete a task. That is the whole app — roughly 45 lines.

| Fact | Value |
|---|---|
| WSGI entrypoint | `deploy_wsgi:app` (wraps `app:app`, adds `/healthz`) |
| Listens on | `5762` inside the container |
| Suggested hostname | `todo.harolditdata.uk` |
| Persistent state | MongoDB (external), database `flask_database`, collection `todos` |
| Authentication | **none** — see section 5 |

---

## 1. Environment variables

The repo reads none today; both variables below are consumed by
`deploy_wsgi.py`, which was added so that no source file had to change.

| Variable | Required | Default | Read by | Notes |
|---|---|---|---|---|
| `MONGO_URI` | **Yes** in a container | `mongodb://localhost:27017` (hardcoded `MongoClient('localhost', 27017)` in `app.py`) | `deploy_wsgi.py` | e.g. `mongodb://mongo:27017/flask_database`. If the URI carries no database name, `flask_database` is used, matching `app.py`. |
| `SECRET_KEY` | No | unset | `deploy_wsgi.py` | `app.py` never sets one and nothing currently uses the session. Set it anyway. |
| `PORT` | No | `5762` | `Procfile` only | The Dockerfile binds 5762 unconditionally. |

`app.py` builds its client at import time, but every route resolves `todos` as a
module global at call time, so `deploy_wsgi.py` rebinds that attribute after
import. No framework internals are touched and nothing depends on import order.

The tidier version is still one line in `app.py`:

```python
client = MongoClient(os.environ["MONGO_URI"])
```

## 2. Build and run

```bash
docker build -t todo:latest .

docker run -d --name todo \
  --restart unless-stopped \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=16m \
  -p 127.0.0.1:5762:5762 \
  --env-file /etc/harold/todo.env \
  --memory 200m --cpus 0.25 \
  todo:latest
```

Nothing is written to disk, so `--read-only` is free here.

`requirements.txt` **was generated by this deployment pass** from the imports in
`app.py`; the repo had none. Its header records which import each line comes
from.

## 4. Frozen-Flask

`app.py` imports `Freezer` at module scope and, under `if __name__ ==
"__main__"`, calls `freezer.freeze()` *before* `app.run()`. Gunicorn never runs
that branch, so the container behaves as a normal dynamic app. Frozen-Flask is
still a hard dependency because of the module-level import.

The committed `build/` directory is a previous static export containing real
ObjectIds from someone's local database. The `.dockerignore` keeps it out of the
image.

## 5. Why this is not "host now"

There is **no authentication and no CSRF protection**. Any visitor can list,
create and delete every to-do in the database. `POST /` and `POST /<id>/delete/`
are wide open, and `GET /<id>/delete/` returns a helpful message confirming the
id exists.

That is fine for a demo behind **Cloudflare Access**, which is how this should be
published: an Access policy on `todo.harolditdata.uk` restricted to your own
email gives it a login without touching a line of code. Without that, do not
publish it — not because it is dangerous, but because it will be defaced by a
scanner within days.
